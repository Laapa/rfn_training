# HANDOFF — полное состояние проекта «Тренировка резонаторов»

Документ для продолжения работы в новом чате. Читать целиком перед любыми изменениями.
Ветка: `claude/busy-cannon-llmzmp` (репозиторий `laapa/rfn_training`). Последний коммит на момент записи — см. `git log`.

---

## 1. Что делаем и для кого

- **Задача.** Новая программа тренировки ВЧ-резонаторов (новое здание, стенд ИЯФ/СКИФ) вместо старой
  `skif.py` (лежит в корне — только как образец; работала с одним резонатором через NI PXI/PyDAQmx + Modbus).
- **Новая программа:** несколько резонаторов одновременно, работа через **Tango** (PyTango), два режима —
  **MANUAL** и **AUTO** (автоматическая тренировка), запуск из **exe**.
- **Пользователь** (пишет по-русски, разговорно, с опечатками) — разработчик; есть «научный» (научный руководитель),
  который задаёт вид интерфейса. Пользователь раньше переписывал код вручную, поэтому код держим **коротким,
  понятным, с комментариями по-русски**.
- **Доступа к железу пока нет.** Всё проверяется на встроенном симуляторе и на **фейковом стенде** (Tango).

## 2. Окружение пользователя

- **Windows**, VS Code, PowerShell. Python **3.12.6** (в PATH был ещё старый 3.8 — окружение создавать через `py -3.12`).
- Папка у пользователя: `C:\rfn_training\rfn-training_fork`.
- Окружение программы: `.venv` (Python 3.12) — `pip install -r requirements.txt`:
  `pytango==9.5.1, PyQt5==5.15.11, pyqtgraph==0.14.0, numpy==1.26.4, taurus==5.5.0`.
- Стенд: **Tango 9.3.4**. PyTango 9.3.4 под Python 3.12 не существует (был до 3.8) → берём **9.5.1** (самая ранняя 9.x
  с колёсами cp312 под Windows).
- Фейковый стенд — отдельное окружение `.venv_fake` (**PyTango 10.3.2 + gevent**), создаётся `fake_server\start_fake.bat`.
  Причина: встроенная база Tango (`tango.databaseds`, SQLite) в PyTango 9.5.1 сломана (см. §8).

## 3. Устройства стенда (дал пользователь)

Путь: `rf2/1e2/<device>`; у других резонаторов отличаются только цифры (`rf3/1e3`, `rf4/1e4` — это **догадка**,
сверить в Jive).

| Устройство | Атрибут / команда | Тип | Что это |
|---|---|---|---|
| mod (модулятор) | `ModSt` | ro bool | «Готов» → лампа RDY |
| | `ModU`, `ModI` | ro bool | АРУ по U / по I |
| | `Ucav` | ro float 0–30 кВ | напряжение резонатора (измер.) |
| | `Ifid` | ro float 0–10 А | ток фидера (измер.) |
| | `UcavSetpoint` | rw float 0–30 кВ | уставка U |
| | `IfidSetpoint` | rw float 0–10 А | уставка I |
| | `ModOn()`, `ModOff()`, `RstAll()` | команды | Вкл ВЧ, Выкл ВЧ, сброс блокировок |
| cav | `Vac` | ro float | вакуум, **в Торр** |
| sspa (усилитель Триада-ТВ) | `SspaPforw`, `SspaPrefl` | ro float 0–8 кВт | падающая / отражённая |
| ctrl | — | | не нужен |

- Фазометра и раздельных «Сброс ГЕН / Сброс ББ» на стенде **нет** → убраны (один «Сброс» = `RstAll`).
- Лампа «Вкл» = стандартный `mod/State` (ON); «Авария» — наша: `State` FAULT/ALARM, нет связи, или автомат сам
  вышел из AUTO из-за ошибки связи (`Trainer.error`, держится до «Сброса» или нового AUTO). Причина — в подсказке лампы.
  На реальном стенде **не проверено**, выставляет ли `mod` State как ожидаем.

## 4. Алгоритм (trainer/core.py) — принятые решения

Источник: `README` пользователя (алгоритм тренировки) + уточнения в переписке.

- Пороги вакуума (больше число = хуже): **Vac0 = Good**, **Vac1 = Bad («стоп»)**, **Vac2 = Very Bad («отказ»)**.
- Шаг вперёд — только после Good и выдержки **dt (Response Delay)**. Между Good и Bad — ждём Good (новый отсчёт не начинается).
  В отсчёте стало ≥ Bad — отсчёт сначала.
- **Very Bad в любой момент → сразу 3 шага назад** (`back_steps`). Потом: стал Good → вперёд (через dt);
  за **Timeout** не стал Good → ещё 3 шага назад, вплоть до Start.
- Start/Stop **вычисляются** из Umin/Umax и направления. Старт — с текущей уставки; если уставка уже на/за Stop (UP/DOWN) — не стартуем.
- Методы: **UP, DOWN** (дошли до Stop → MANUAL + фанфары), **ZONE** (туда-обратно бесконечно),
  **SAW «пила»** (вверх, на Umax одна выдержка, резко в Umin). В UI — список «Вверх / Вниз / Zone / Пила».
  Пользователь говорил «три метода» — оставили все четыре (если «Пила» не нужна — убрать одной строкой в `METHODS`).
- Шагаем и сравниваем **по уставке** U (не по измеренному).
- Кнопки **Stop/Start** — пауза шагов вперёд без выхода из AUTO (откат при Very Bad работает и на паузе); **Reverse**.
- **Нет «Готовности» (ModSt=False) → автомат ждёт**, уставку не трогает (иначе после включения ВЧ напряжение прыгнуло бы).
- **Ошибка связи → MANUAL**, напряжение не трогаем.
- Время алгоритма — по настоящим часам (`time.monotonic()` × 1000/tick_ms в main_window), не по числу тиков:
  если тик задержался из-за Tango, dt/Timeout всё равно честные. tick_ms < 1000 ускоряет (для симулятора).
- Сравнение уставки со Stop — с допуском `EPS = 1e-3` кВ (float32 на устройстве). `check()` требует 0 < Good
  и известный метод. Смена метода/Reverse сразу меняет `direction` (`Trainer.set_sequence`).
- Предел: `u_limit` = 30 кВ (`u_max_kv` в config), ток — `i_max_a` = 10 А.
- **Ток фидера** — отдельная уставка, общая для MANUAL и AUTO, алгоритм её не трогает.
  Гипотеза (не подтверждена): АРУ держит U, а уставка I — потолок; «АРУ: I» загорается при упоре в ограничение.
  Открытый вопрос к коллегам: в каком режиме АРУ тренируют.

## 6. Интерфейс — текущий вид и история

**Текущий (по эскизу научного, коммит 4d1a43f):** окно резонатора сверху вниз:
1. Лампы: Вкл (mod/State) · RDY (ModSt) · АРУ U · АРУ I · **Авария**; справа кнопки **Вкл / Выкл / Сброс** (обычные кнопки через поток-работник).
2. «Значения»: Ucav, Iфид, Pпад, Pотр, Vac (TaurusLabel, только чтение; Vac цветом по порогам, Pотр красная > u_otr_max);
   под Ucav/Iфид — поля «уставка U» и «уставка I» (StepField, пишут через нашу логику; U заблокирована в AUTO).
3. «Тренировка»: Umax, Umin, dU, dt, Timeout (StepField). «Вакуум»: Vac2/Vac1/Vac0 (−/+ по 2-й значащей цифре),
   галка «AUTO», лампа автомата, Start/Stop/Reverse. «Метод»: радиокнопки с картинками.
4. «Графики»: Ucav(t) (измер. + уставка), Vac(t) лог-шкала с пунктирами порогов; кнопка «V(U) ↗» — отдельное окно.
5. Строка состояния: ▲/▼ Start→Stop · состояние автомата, последнее сообщение, часы.

Окно «Обзор»: таблица (режим, состояние, U, вакуум, Start→Stop), галка открывает окно резонатора
(чётные — слева, нечётные — справа, пол-экрана), «Просмотр записей…». Закрытие окна резонатора
не останавливает тренировку; закрытие «Обзора» = выход (спросит, если AUTO).

**Требования пользователя к дизайну (важно соблюдать):**
- Интуитивно для тех, кто работал со старой программой; структурированно; **современно, но не «перебор»**.
- **С ноября: обычное классическое оформление PyQt** (системный стиль, без своих тем, QSS, плашек и рисованного
  тумблера; тёмной темы нет). Блоки — обычные `QGroupBox` с подписью. Цвет — только по смыслу (лампы, пороги
  вакуума, Pотр > предела). «Максимально просто, инженерно, никакого красивого фронта» — слова пользователя.
- **Графики в приоритете** при любом размере окна; поля плотные.
- Окно резонатора должно помещаться в **пол-экрана** (два резонатора рядом, 950×1040 на Full HD).
- Не выдумывать лишних элементов (лампу «Связь» убрали — её не было). Что научный не нарисовал и пользователь
  сказал убрать: U НО, ток насоса, A/Торр, пороги в амперах, «Новая сессия», «Открыть запись» в окне резонатора.
  Часы — оставить. Вкладки старой программы «Графики/Смотрелки/Мусом/Настройки» — не нужны.

**История вариантов (чтобы не повторять ошибок):** табличный прототип → тёмные «карточки» (отвергнуто: «перебор») →
копия старой «Главной» в цветных рамках (отвергнуто: «Windows XP») → старая раскладка + современный вид → уплотнение
ради графиков → эскиз научного + Taurus → **то же, но в классическом виде Qt (текущий)**.

## 7. Taurus

- Научный хочет виджеты Taurus: `TaurusLabel`, `TaurusLed`, `TaurusValueSpinBox`, `TaurusCommandButton`.
- Решение (согласовано): Taurus **только для показа** (значения, лампы) + кнопки команд. Уставки — через нашу логику
  (`StepField` в стиле TaurusValueSpinBox), чтобы в AUTO никто не писал в устройство мимо автомата.
- `gui/views.py`: для `TangoResonator` — Taurus, для симулятора — обычные виджеты (тот же вид).
- Формат чисел: `"{0.magnitude:.2f}"` / `"{0.magnitude:.1e}"` (иначе Taurus дописывает единицы/«dimensionless» для Torr).
- Работает с обычным `QApplication` (TaurusApplication не нужен).
- **Без базы Tango Taurus не работает**: баг разбора `#dbase=no` в имени атрибута + опрос значений идёт через базу.
  Поэтому фейк сделан с базой (§8).
- **В exe**: Taurus ищет схемы по папкам на диске → в exe «Cannot create Factory for 'tango'». Лечится
  `tauruscustomsettings.EXTRA_SCHEME_MODULES = ["taurus.core.tango"]` при `sys.frozen` (сделано в views.py);
  в `training.spec` — collect_submodules/collect_data_files/copy_metadata для taurus и pint.

## 8. Фейковый стенд (fake_server)

- `start_fake.bat` (Windows): создаёт `.venv_fake` (py -3.12, PyTango 10.3.2, gevent), запускает `fake_rf.py`.
- `fake_rf.py`: поднимает **свою базу Tango** (`python -m tango.databaseds.database --port 10123 2`, SQLite в
  `fake_server/db_data`), регистрирует `FakeRF/fake` с устройствами `rf2/1e2, rf3/1e3, rf4/1e4` (mod/cav/sspa),
  запускает device-сервер обычным `tango.server.run` (в основном потоке!), пишет/обновляет `fake_config.json`
  (`tango_host: 127.0.0.1:10123`, сохраняет `settings` окон). Ctrl+C гасит и базу.
- «Физика»: U выходит на уставку 2 кВ/с; «чистые» до 8/11/14 кВ, выше — случайные пробои (`spark_rate=0.05`);
  вакуум откачивается ×0.9/с; блокировка при вакууме > `TRIP_TORR = 1e-7` (ModSt=False, State=FAULT, U→0),
  снять: RstAll, затем ModOn (когда вакуум откачается). `cav/Spike()` — пробой вручную. State: ON/OFF/FAULT.
- Грабли, на которые наступили:
  - `MultiDeviceTestContext` в потоке на Windows → «Class DServer is not initialised» → перешли на `run()` в основном потоке.
  - Встроенная база в **PyTango 9.5.1** сломана: ищет SQL-схему в текущей папке, дедлок при создании БД
    (ThreadPoolExecutor(1)), «--embedded» с NameError, DbGetServerList рекурсия, сервер «не определён в базе».
    В **PyTango 10.3.2** работает сразу → отдельное окружение для фейка.
  - Сначала порог блокировки был 3e-8 → «Готовность» постоянно тухла. Подняли до 1e-7.
  - У пользователя (сеть ИЯФ) pip в `.venv_fake` не нашёл numpy («from versions: none») → `start_fake.bat` копирует
    numpy из `.venv` программы; при неудаче удаляет недоделанный `.venv_fake`; проверяет `import tango, gevent`.
  - `fake_rf.py` из `.venv` (PyTango 9.5.1) - понятное сообщение «нужен PyTango 10, запускай start_fake.bat».
  - Нет Taurus в окружении → окно работает на обычных виджетах (`views.TAURUS`), в журнале подсказка.
  - Имя резонатора с «/» ломало папку данных → имя папки очищается от запрещённых символов.

## 8а. Устойчивость (ревью, ноябрь)

- `TangoResonator` подключается к устройствам лениво (в `_call`), поэтому программа открывается и без стенда/базы:
  прочерки, «Авария» с причиной, в журнал — только момент обрыва и восстановления связи.
- `main.py`: `sys.excepthook` → `error.log` рядом с config + окно с ошибкой (в exe нет консоли; PyQt5 иначе молча
  закрывается при ошибке в обработчике).
- При обрыве связи в AUTO галка AUTO сразу встаёт в MANUAL. Кривые `settings` в config → значения по умолчанию.

## 8б. Потоки (после зависания у пользователя)

- У пользователя на Windows окно «Не отвечает» после остановки фейка: вызов Tango к остановленному устройству/базе
  на Windows висит секунды (в Linux - отказ мгновенно), а вызовы шли из потока окна.
- Теперь: `trainer/worker.py` - поток на резонатор. Он крутит `Trainer.tick` и читает `Snapshot`
  (m, u_set, current, error, stamp). Окно (`update_view`) берёт снимок; снимок старше 5 тиков = «не отвечает».
  Уставки, команды, AUTO, Start/Stop/Reverse, метод -> `worker.do(...)`. Галка AUTO = состояние автомата
  (пока очередь не пуста - не трогаем). Журнал из потока -> `log_signal` -> окно.
- Кнопки Вкл/Выкл/Сброс - обычные QPushButton через работника (TaurusCommandButton выполнял команду в окне).
  Taurus остался для показа значений и ламп (у него свой поток опроса).
- Проверено: 3 «мёртвых» резонатора (каждый вызов висит 2 с) - окно не замирает дольше 70 мс;
  фейк: AUTO -> убить фейк -> MANUAL, «Авария» -> поднять фейк -> «Связь восстановлена».

## 12. Как работать ассистенту (договорённости и приёмы)

- Отвечать **по-русски**, просто, структурированно; честно писать, что проверено, а что нет.
- Коммитить и пушить в `claude/busy-cannon-llmzmp` после каждого законченного шага (стоп-хук требует чистое дерево).
  PR не создавать без просьбы.
- Проверка GUI без экрана: `QT_QPA_PLATFORM=offscreen`, `widget.grab().save(png)`, смотреть картинку.
  Виртуальный экран offscreen = 800×600 → подменять `QApplication.primaryScreen` на 1920×1040.
  Taurus обновляется только при живом цикле событий: `QTimer.singleShot(..., quit)` + `app.exec_()`.
- Окружения в scratchpad: `venv312` (Py 3.12, PyTango 9.5.1, PyQt5, pyqtgraph, taurus, pyinstaller) — как у пользователя;
  `venvfake` (Py 3.12, PyTango 10.3.2, gevent) — для фейка. Создаются через `uv venv -p 3.12` / `uv pip install`.
  Системный python3 (3.13) — PyTango 10.3.2, PyQt5 — для быстрых тестов.
- Фоновые процессы фейка гасить `pkill -9 -f fake_rf.py; pkill -9 -f databaseds` (иначе порт занят).
- Нельзя `rm -rf` по относительным маскам после `cd` — блокирует защита; удалять конкретные пути или не удалять.
- Код короткий, с комментариями по-русски; не плодить лишнего; ничего из согласованного функционала не убирать без спроса.
