# Шпаргалка: EPICS для программы тренировки резонаторов

## Главное в трёх строках
- **PV** — переменная стенда с именем: `RF2:MOD:Ucav` (напряжение). Её можно прочитать или записать.
- **IOC** — программа на стороне стенда, которая держит эти переменные (как device-сервер в Tango).
- **Команд нет**: «Вкл / Выкл / Сброс» = записать **1** в нужный PV.

## Что узнать у коллег
1. **Имена PV** для одного резонатора (и чем отличаются у других — обычно только `RF2` → `RF3`).
2. **Адрес IOC** (или шлюза CA Gateway), например `10.0.0.6`.
3. **CA или PVA**. Программа сделана под **CA** (если только PVA — нужна доработка).
   Ещё полезно: единицы (кВ? Торр или ток насоса в А?), разрешена ли запись с нашего ПК.

Нужные имена PV:

| Что | В config (`"pv"`) | По умолчанию (фейк) | Тип |
|---|---|---|---|
| U измеренное | `Ucav` | `RF2:MOD:Ucav` | читаем |
| I фидера измеренный | `Ifid` | `RF2:MOD:Ifid` | читаем |
| уставка U | `UcavSetpoint` | `RF2:MOD:UcavSetpoint` | пишем и читаем |
| уставка I | `IfidSetpoint` | `RF2:MOD:IfidSetpoint` | пишем и читаем |
| «Готовность» | `ModSt` | `RF2:MOD:ModSt` | читаем 0/1 |
| АРУ U / АРУ I | `ModU` / `ModI` | `RF2:MOD:ModU` / `ModI` | читаем 0/1 |
| лампа «Вкл» | `RfOn` | `RF2:MOD:RfOn` | читаем 0/1 (нет — `null`) |
| авария модулятора | `Fault` | `RF2:MOD:Fault` | читаем 0/1 (нет — `null`) |
| Вкл / Выкл / Сброс | `ModOn` / `ModOff` / `RstAll` | `RF2:MOD:ModOn` ... | пишем 1 |
| вакуум | `Vac` | `RF2:CAV:Vac` | читаем (Торр; если ток в А — `"vac_is_current": true`) |
| Pпад / Pотр | `SspaPforw` / `SspaPrefl` | `RF2:SSPA:SspaPforw` ... | читаем |

## Куда вписать — epics_config.json рядом с программой (код не трогаем)
При запуске программа спросит «Tango или EPICS?» → **EPICS** → берёт `epics_config.json` (нет — создаст).
```json
{
    "epics_ca_addr_list": "10.0.0.6",
    "resonators": [
        {"name": "Резонатор 2", "type": "epics", "prefix": "RF2",
         "pv": {"Ucav": "НАСТОЯЩЕЕ:ИМЯ", "Vac": "НАСТОЯЩЕЕ:ИМЯ", "UcavSetpoint": "НАСТОЯЩЕЕ:ИМЯ"}}
    ]
}
```
- `epics_ca_addr_list` — адрес IOC; несколько — через пробел.
- в `"pv"` — только те имена, что отличаются от шаблона `<prefix>:<MOD|CAV|SSPA>:<имя>`.
- `null` — такого PV на стенде нет.
- Tango- и EPICS-резонаторы можно держать в одном config вместе.

## Если пишет «нет ответа от PV»
1. **Неверное имя** — сверить с коллегами (большие/маленькие буквы важны).
2. **Неверный адрес** или IOC в другой подсети — проверить `epics_ca_addr_list`.
3. **Брандмауэр Windows** — разрешить Python / Training.exe (порты UDP 5064, 5065).
Проверить одно имя вручную (PowerShell, в .venv):
```
$env:EPICS_CA_ADDR_LIST="10.0.0.6"; $env:EPICS_CA_AUTO_ADDR_LIST="NO"
python -c "import epics; print(epics.caget('ИМЯ:PV'))"
```
`None` = не нашлось; число = всё работает.
Читается, но не пишется — запись запрещена (шлюз только на чтение или права IOC).

## SP / RB / I — если у уставки несколько PV
| | что значит | пример (кондиционер) |
|---|---|---|
| `-SP` | что мы **попросили** | нажал на пульте 22° |
| `-RB` | что прибор **принял** | табло: «уст. 22°» |
| `-I` | что **реально** получилось | термометр: 25° |
Алгоритм шагает от **уставки** (SP), не от измерения (I). Если у стенда SP и RB разные PV — сказать, нужна мелкая доработка.

## Первый запуск на стенде
1. Вписать адрес и имена в config.
2. Запустить в **MANUAL**, сравнить цифры с панелями коллег.
3. Совпало — AUTO в маленьком диапазоне (например, Umin 1, Umax 3, dU 0.2).

## Проверить без стенда
```
fake_server\start_fake_epics.bat          (окно 1, держать открытым)
```

## Словарик
| Слово | Значит |
|---|---|
| PV | переменная с именем |
| IOC | сервер EPICS на стороне стенда |
| record, запись | то, что стоит за PV внутри IOC (тип + поля) |
| `.EGU` | единицы PV (`RF2:CAV:Vac.EGU`) |
| ai / ao | число: читаем / пишем |
| bi / bo | 0/1: читаем (лампа) / пишем (кнопка) |
| get / put / monitor | прочитать / записать / подписаться на изменения |
| CA / PVA | два «языка» EPICS; у нас CA |
| CA Gateway | шлюз между сетью стенда и офисной сетью |
